# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Payroll accounting** — approving a payroll run now posts the accrual to the general ledger (remuneraciones 621, bonificación 622, EsSalud 627 against AFP 407, ONP 4032, quinta categoría 4017, EsSalud 4031 and remuneraciones por pagar 411), and paying it posts the settlement against caja (101) or banco (1041). `POST /payroll-runs/{id}/pay` accepts an optional `paymentMethodId` (CASH → caja, otherwise banco). The entry is posted before the status is committed, so a ledger rejection leaves the run unapproved. Migration `Version20261106000000_payroll_accounts` seeds the accounts; the PCGE mapping should be confirmed with the tenant's accountant. Runs approved before this change have no entry yet.
- **Despatch guides (GRE remitente)** — guides are validated on creation (series `T###`, transfer date, Catálogo 20 reason, recipient/carrier/driver documents, vehicle plate for private transport, ubigeos, weight, items) instead of failing at SUNAT. The "Otros" reason description and the originating invoice/boleta (`relDoc`) are now sent. A guide is only locked once SUNAT accepts it (CDR code 0 or 4000+); rejected or errored guides can be sent again.
- **Accounts-payable aging** — `GET /api/supplier-bills-aging?as_of=` returns open supplier-bill balances by days past due (not due / 1–30 / 31–60 / 61–90 / 90+) per supplier with currency totals and a bill-level detail; `GET /api/supplier-bills-aging/export?view=summary|detail` downloads it as XLSX (gated by `excel_export`). Cut-off dates in the past are rejected because balances are the current ones.
- **Build version in the UI** — the deployed semver tag now shows on the login screen (`.brand-version`) and in the app footer. Sourced from the `APP_VERSION` env var, set in the prod/staging image from the git tag (`build-image.yml` → Docker `ARG`/`ENV`); unset locally resolves to `dev`, which both surfaces hide. Replaces the half-wired `.version` file lookup in `SettingsExtension`.
- **"Imprimir logo en comprobantes" toggle** — `TenantSettings.printLogo` (writable via `PATCH /api/tenant/settings` all along, default on) now has a UI control: a new "Comprobantes" section in Configuración → General. It had no row in the generic `config` list and wasn't among the typed toggles, so a tenant could never turn the ticket/A4 logo off.
- **Sales report — "Ventas por método de pago (detallado)"** (`payment-method-breakdown`) — one row per comprobante in the range, a column per active payment method with the amount paid via that method, plus "Total pagado" / "Total comprobante", and a footer TOTALES row summing every method column. New `src/Sales/Report/PaymentMethodBreakdownReport.php` (tagged `app.sale_report`, pivots dynamically over `payment_method`), reachable from Consulta de ventas → report dropdown. Uses the existing `Nubit\Platform\Export\XlsExporter`; gated by the `excel_export` feature like the other exports.
- **Integration platform (`src/Integration`, ADR-017)** — a reusable machine-to-machine surface, validated by SUNAT emission for `nubit-control`'s own hosting sales:
  - **Tenant-scoped API keys** (`nb_<env>_<tenant>_<secret>`, SHA-256, revocable) behind a new `integration_api` firewall on `^/api/v1`; `app:integration:api-key:create`.
  - **`POST /api/v1/documents`** builds a CPE without a `Sale` (`SyntheticVoucherFactory` + an optional-`Voucher` seam on `BillCreateUseCase`/`BillSendUseCase`), idempotent on `external_id`, dispatched through the existing SUNAT pipeline; `GET /api/v1/documents/{reference}` for polling.
  - **Outbound webhooks** — transactional outbox (`IntegrationEvent`), HMAC signatures (`Nb-Signature`, Stripe-style), per-endpoint retries with dead-letter and auto-disable, `app:integration:webhooks:tick` (scheduled every minute) and `:replay`. Event catalog: `document.accepted` / `rejected` / `voided`.
  - **Settings UI** (Configuración → Integraciones) to manage API keys and webhook endpoints, with one-time secret reveal, a delivery log and manual retry, served by `src/Integration/Controller/Settings/*` under `perm:settings.edit`.
  - Migrations `Version20260830140000`–`160000` (per-tenant: `integration_api_client`/`_key`, `integration_document`, `integration_event`, `integration_webhook_endpoint`/`_delivery`).
- **POS settings** — New `auto_print` tenant setting and a "Punto de venta" section in Configuración → General with typed toggles for **Emitir boleta/factura por defecto** (`autoInvoice`) and **Impresión automática** (`autoPrint`). The POS now honours both as per-tenant defaults; the General tab is reachable by every tenant again (previously hidden for single-store tenants). Migration `Version20260828120000_tenant_settings_auto_print` (default on, no behaviour change for existing tenants).
- **SLICE-CP-02** — Granular role system for the control-plane admin panel: three roles (`ROLE_CP_VIEWER` ⊂ `ROLE_ADMIN` ⊂ `ROLE_SUPER_ADMIN`) with security hierarchy, `#[IsGranted]` guards on all controllers, and Twig `is_granted()` template guards. Destructive tenant actions require `ROLE_SUPER_ADMIN`.
- **SLICE-CP-01** — Login UI for the admin panel: `form_login` replaces `http_basic`, standalone Bootstrap 5.3 login page, CSRF protection, remember-me (7 days), brute-force throttling (5 req/min), and functional logout with session invalidation.
- **SLICE-CP-03** — Admin user management UI (ROLE_SUPER_ADMIN only): full CRUD via `AdminUserController` + `AdminUserRepository` (DBAL), password strength/confirm validation, AJAX active-toggle, and audit log for all operations.

### Fixed
- **Per-tenant feature override could not be saved** — `TenantFeatureOverrideManager::setOverride()` wrote an `updated_at` column that `tenant_feature_overrides` never had, so adding/editing an override from the control-plane Features tab failed with `SQLSTATE[42S22] Unknown column 'updated_at'`. The manager's unit test mocks the DB connection, so it slipped through.
- **Company logo missing from ticket/A4 PDFs** — `LogoProvider::embedded()` swallowed every storage read error with a bare `catch { return '' }`, so a logo that can't be read just vanishes with no trace. It now reads through `Nubit\Platform\Filesystem\FileManager` (the same service the media library uploads with, so the tenant prefix always matches) and logs a warning with the attempted path when the read fails.
- **Control-plane tables — empty band before the row-actions column** — `@nubitio/ui` sets `table-layout: fixed` on any DataTable with row actions, splitting leftover width equally across the data columns; tables with few/narrow columns (tenants, users) showed a wide gap before the sticky `···` cell. Overridden to `table-layout: auto` in the control-plane bundle.
- **Invoice quota is per calendar month again** — `TenantQuotaService` counted every quota resource with a lifetime `SELECT COUNT(*)`, so a plan's `invoices` allowance (free 500, basic 5000) was compared against the tenant's all-time `tax_document` count and never reset — a tenant that ever hit the number stayed blocked forever. `invoices` is now classified as a monthly quota in `TenantResourceCatalog` (`monthlyQuotaDateColumn`) and its usage — in both `check()`/`enforce()` and the control-plane Usage tab — is scoped to the current calendar month in `America/Lima` (resets on the 1st). `users`, `customers`, `products`, `branches`, `storage` stay lifetime caps. No data migration; over-limit tenants are unblocked automatically.
- **Control plane — "Cambios en las últimas 24 h" restored** — the tenant Usage tab lost its 24-hour delta table (comprobantes emitted, clientes/productos added, etc.) in the Twig→React migration even though the API kept returning `usageDeltas`. `UsageTab` renders it again (Recurso / Hace 24 h / Ahora / Cambio), the payment-quota row is labelled *mensual*, and `types.ts` now types `usageDeltas` correctly.
- **Fresh-tenant setup** — `InitialSetupService::configure()` no longer wraps the whole sequence in a manual outer transaction. That forced every nested `$em->flush()` (including `AuditTrailListener`'s second flush in `postFlush`) plus the seeders' own transactions into deep DBAL savepoints, which broke with `SQLSTATE[42000] 1305 SAVEPOINT DOCTRINE_2 does not exist` on a clean tenant DB — blocking `app:tenant:setup`, `app:demo:seed` and `POST /api/test/e2e/seed`. Each unit now manages its own transaction. CI never caught this because it provisions from a baseline dump with `configured = true`.
- **Dashboard — last-7-days chart** — `pickLast7SalesDays` matched sales rows by day-of-month across months, so early in a month it pulled the *current* month's future days (all zero) and emitted duplicate weekday labels, which collapsed the chart's category axis (tooltips read `S/ 0` on the real bar). It now only matches rows in the current month and derives labels from the actual date.

### Changed
- **Feature entitlements are code-defined** — `PlanFeatureManager::FEATURE_KEYS` (a 15-key constant) is replaced by `src/ControlPlane/Billing/Feature/FeatureCatalog.php`: one entry per key with label, category (*Comercial* / *Módulos ERP*), config flag and per-plan defaults (pattern: `PermissionCatalog`). A compiler pass (`RequireFeatureKeyPass`, wired in `src/Kernel.php`) fails the build if a `#[RequiresFeature]` / `hasFeature()` / `IS_GRANTED('FEATURE_…')` names an undeclared key. New `app:features:sync` reconciles `plan_features` to the catalogue (gap-fill; `--force` to reset) and runs after migrations — adding a feature no longer needs its own migration. The control-plane plan-features matrix and per-tenant override picker now list **all** keys grouped and operator-editable; `payroll`, `general_ledger`, `bank_reconciliation`, `fixed_assets`, `expense_reports`, `recurring_billing` were previously invisible. See ADR-013 amendment.
- **Dashboard rebuilt on Recharts** — the main dashboard (`/#/dashboard`) is now a fully-custom React + Recharts view (KPI row, 7-day sales bars, 12-month area trend, payment-method horizontal bars, breakdown tables) instead of the declarative `@nubitio/dashboard` config engine. Payment methods are shown as sorted horizontal bars rather than a donut. The "Hoy" block is folded into the dashboard as a slim attention strip (only items needing action), and the onboarding shortcuts only appear while tenant setup is incomplete. The data layer (`GET /api/bi/overview` → `mapEfactDashboardPayload`) is unchanged.
- **Modern SaaS restyle** — neutral near-black dark / off-white light theme tokens (killed the Tailwind-slate blue tint), softer low-contrast borders, flatter shadows (dropped the white inset ring in dark). Retouched the app shell (rounded inset sidebar items instead of full-bleed rows + 3px accent bar, softer header/panel dividers) and the user menu (neutral-grey hover, rounded inset items, roomier dropdown). Grid filter-row operator selector is neutral instead of an accent-tinted pill. Radii widened a step. Theme `--accent-color` fallback aligned to `@nubitio/ui`'s `DEFAULT_ACCENT` (`#1a6fd4`) — the running accent is still the per-tenant setting.

### Removed
- Orphaned legacy dashboard code superseded by the Recharts rebuild: `DashboardHero/Charts/Rankings/StatusBar/Operations`, `useDashboardMetrics`, and the `efactDashboardConfig` declarative config. `@nubitio/react-admin` now has no JS importers in the frontend (only its shared `style.css`).
